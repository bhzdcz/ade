# Intent: ADE marketing site (`ade.ir`) via public `bhzdcz/ade-site`

Accepted by Behzad (product owner) on 2026-09-05.

## Problem

ADE is stamped on product docs with canonical URL `https://ade.ir`, but there is no public marketing landing. Visitors and Behzad need a dark-first pixel-art site that explains the artifact chain and links to the product — without hosting the platform runtime or publishing Pages from the private product repo.

## Proposed outcome

1. Public GitHub repo `bhzdcz/ade-site` serves a static marketing landing via GitHub Pages.
2. Canonical site at `https://ade.ir` (Behzad configures DNS; agents document records only).
3. Product SoT stays `bhzdcz/ade`: intent, spec, and plan for this work live here; marketing ↔ product is **links only**.
4. Landing explains ADE (intent → spec → plan → diff → review → gates → maintain) with pixel visual system; CTAs to GitHub product and `docs/how-to-run.md`.

## Constraints

- Do not publish Pages from private `bhzdcz/ade`.
- Do not run runner/dashboard/auth on the marketing site.
- Leadito does not Build.
- Agents do not change Behzad’s DNS.
- Do not present stage bots as the product; do not claim the landing hosts the platform runtime.

## Open questions

Defaults stand (see accepted spec): site MIT; apex canonical; www CNAME to `bhzdcz.github.io`; no light-mode toggle in v1.

## Success criteria

### Leading

- Accepted intent → spec → plan on `bhzdcz/ade`
- Public `bhzdcz/ade-site` with landing, CNAME, Pages workflow, DNS docs
- PRs open (not merged by agents) for product seed and site landing

### Lagging

- `ade.ir` resolves after Behzad DNS + Pages HTTPS
