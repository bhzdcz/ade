# Intent: Commercial launch

## Problem

ADE has useful workflow contracts but no portable installation, public onboarding, or revenue path. The site links to a private repository. Current hook success responses explicitly grant permissions, path checks do not canonicalize traversal, and tests mutate the working repository.

## Proposed outcome

A tested, installable Claude Code toolkit and a polished public site with an interactive example, accessible documentation, and honest commercial offers. Paid onboarding is the first revenue experiment; a public core and optional sponsorship are the growth path.

## Constraints

Behzad explicitly authorized review, planning, rebuilding, additions and modifications in this conversation, on branches only. This supersedes earlier scope restrictions for the site and v1. Implementation authorization is not a merge, release, payment-account, or repository-visibility approval. Preserve historical records. Do not publish private product sources to the public site.

## Open questions

Public contact, donation destination, payment provider, and eventual core visibility remain owner configuration. Do not fabricate them.

## Success criteria

### Leading

Installer preserves existing files and settings; isolated tests cover real failure paths; public site works without product-repo access; complete branch PRs and validation evidence.

### Lagging

Measure qualified inquiries and completed installations before expanding into subscriptions.
